Implementation complete, and a dedicated tester (`monitor-tests`) has since written and validated a full `tests/` regression suite (5 files, 398 tests) against all 14 acceptance criteria, including mutation-testing the authorization check, the monitor-chat exclusion, and the redaction rules to confirm the suite actually catches regressions there. Five rounds of lead/tester review found and fixed real issues before this state: the original delivery design didn't hold up under Telegram's real per-chat rate limit (redesigned to a single packed pump loop per destination chat); `/monitor_here` had no real authorization check (now owner-only on the supervisor's bot via a required `monitor.ownerUserId`); the monitor destination chat itself wasn't excluded from being treated as a conversation; a DM-destination configuration could have locked the owner out of every agent (fixed); and two redaction gaps (JSON/dict-quoted secret keys, connection-string passwords, opaque Bearer tokens). Reconciled with `main` at `9199534` (this PR's own `test-home-sandbox` fix, which the feature branch had already carried independently). Verified on the merged result: `pnpm run build` clean, `pnpm test` full suite green, real `~/.tgcc/config.json` mtime unchanged across the run. **Not yet deployed** — deployment (adding a `monitor` config block with `ownerUserId`, creating the destination supergroup, restarting `tgcc`, running `/monitor_here`) is a separate authorized step after merge. Plan/backlog/log: `work/agent-conversation-monitor/`. Branch: `feat/agent-conversation-monitor`.
